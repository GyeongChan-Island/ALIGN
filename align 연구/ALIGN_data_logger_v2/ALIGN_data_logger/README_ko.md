# ALIGN 실측 데이터 수집 안내

ESP32-WROOM-32 + MPU6050 두 개(0x68, 0x69), 목표 50Hz.
이 패키지에는 실측 데이터나 학습 모델이 없습니다. 실제 보드에서 확인 후 사용하세요.

## 1. 전원·배선·장착 확인

- ESP32 개발보드는 데이터 통신 가능한 USB 케이블로 PC에 연결합니다. WROOM-32 모듈 단품은 USB 개발보드와 다르며 안정된 3.3V 전원과 USB-UART 구성이 필요합니다.
- 전원을 끈 상태에서 배선을 확인합니다. 두 센서 GND와 ESP32 GND를 공통 연결합니다.
- 두 센서 SDA → GPIO21, SCL → GPIO22. IMU1 AD0 → GND(0x68), IMU2 AD0 → 3.3V(0x69). AD0를 떠 있게 두지 마세요.
- MPU6050 모듈의 VCC 허용 전압은 모듈 회로/설명서를 확인하세요. 센서 칩 전원과 레귤레이터가 있는 모듈 입력 전압은 다릅니다. ESP32 I2C 신호와 풀업은 3.3V 기준이어야 합니다. SDA/SCL/AD0에 5V를 넣지 마세요.
- 선을 짧게 고정하고 풀업 유무를 확인합니다. 두 모듈의 풀업이 병렬 연결될 수 있으므로 무조건 저항을 추가하지 마세요. 전원 LED만으로 통신 성공을 판단하지 않습니다.
- 신체 부착 위치, 축 방향, 센서 번호를 기록하고 모든 세션에서 동일하게 유지합니다. 착용 후 잠시 정지하여 안정화합니다.

## 2. Arduino 업로드와 초기 확인

1. Arduino IDE에 Espressif의 `esp32` 보드 패키지를 설치합니다. 보드에 맞는 설정(일반 ESP32 개발보드이면 보통 ESP32 Dev Module)과 실제 포트를 선택합니다.
2. `ALIGN_logger/ALIGN_logger.ino`를 엽니다. 폴더명과 파일명은 동일해야 합니다. 별도 MPU 라이브러리는 필요 없습니다.
3. 업로드합니다. 시리얼 모니터를 115200 baud로 열고 EN/RESET을 눌러 다음을 확인합니다.
   `#INIT,0x68=OK,0x69=OK`와 `#READY,...`.
   FAIL이면 전원·공통접지·주소·배선을 확인한 뒤 재시작하세요. WHO_AM_I 값은 MPU6050이라면 두 주소 모두 0x68입니다. v2는 다른 ID를 경고로 출력합니다. 경고가 있으면 센서 모델과 변환 계수를 확인하기 전 학습에 사용하지 마세요.
4. 모니터 입력에 `S`를 보내면 헤더와 숫자 행이 나옵니다. `X`를 보내면 멈춥니다.
5. 정지 상태에서 각 센서 가속도 벡터 크기가 대략 1g, 각속도가 대략 0deg/s인지 확인합니다. 각 축이 모두 0이어야 하는 것은 아닙니다. 온도·장착·센서 오프셋에 따른 차이를 확인하세요. 이 코드는 바이어스 보정을 수행하지 않습니다.
6. **Python 실행 전 시리얼 모니터와 시리얼 플로터를 닫습니다.** 한 COM 포트를 두 프로그램이 동시에 사용하면 충돌합니다.

## 3. Windows Python 준비와 실제 포트 선택

ZIP을 압축 해제하고 `collect_csv.py`가 있는 폴더에서 PowerShell을 엽니다. Python 3.10 이상이 필요합니다. 아래 `py`가 없으면 설치된 Python의 `python` 명령으로 바꿉니다.

```powershell
py -m pip install -r requirements.txt
py collect_csv.py --list-ports
```

장치 관리자 → 포트(COM 및 LPT), Arduino IDE의 포트, 위 목록을 대조합니다. USB를 뺐다 다시 꽂아 나타나는 포트를 확인하면 좋습니다. **아래 COM5는 예시이며 실제 연결된 COM 번호로 반드시 바꾸세요.** 이 패키지를 만든 환경에서는 사용자의 실제 보드 포트를 확인할 수 없습니다.

## 4. 세션별 라벨로 저장

라벨 규칙: `0 = 미리 정한 기준의 정상 자세`, `1 = 미리 정한 기준의 불량 자세`.
센서값이 자동으로 라벨을 판정하는 것이 아닙니다. 관찰·실험 프로토콜로 자세를 확인하고 사용자가 지정합니다.
먼저 자세를 잡고 안정화한 뒤 실행하세요. 한 세션에서는 라벨을 바꾸지 않습니다.

```powershell
py collect_csv.py --port COM5 --label 0 --subject P01 --seconds 60
py collect_csv.py --port COM5 --label 1 --subject P01 --seconds 60
```

두 명령은 한 번에 한 개씩 실행합니다. 첫 명령 종료 후 다음 자세를 취하고 두 번째 명령을 실행합니다.
중간 종료는 Ctrl+C입니다. 부팅 대기 약 3초 후 수집하며, 첫 유효 샘플부터 지정 시간 동안 저장합니다. 종료 직전 통신 중인 행은 저장되지 않을 수 있습니다.
라벨당 한 세션으로 충분하다고 보지 말고, 여러 독립 세션과 피험자를 계획하세요. P01 등 익명 ID를 사용합니다.

기본 저장 위치는 **스크립트 폴더 아래 `data`**이며 실행 시 절대 경로가 출력됩니다. 다른 위치는 다음과 같이 지정합니다.

```powershell
py collect_csv.py --port COM5 --label 0 --subject P01 --seconds 60 --out "C:\ALIGN\data"
```

세션마다 날짜·시간·무작위 ID가 붙은 별도 파일이 생깁니다.
- `.csv`: 학습용 숫자와 세션 정보
- `.summary.json`: 행 수, 실제 수신 주파수, 누락, 경고, 종료 이유
- `.events.txt`: 초기 상태/읽기 실패 등 수집 중 받은 메시지

## 5. CSV 열과 단위

`session_id,subject_id,label,seq,time_us` 다음에 IMU1 6개, IMU2 6개 채널이 있습니다.
각 센서 채널 순서는 `ax_g, ay_g, az_g, gx_dps, gy_dps, gz_dps`입니다.

- 가속도: **g**, 중력 포함, ±2g 범위, 16384 LSB/g.
- 자이로: **deg/s (= dps)**, ±250deg/s 범위, 131 LSB/(deg/s).
- `time_us`: ESP32 부팅 이후 마이크로초. 64비트 타이머를 사용하며 PC 시각/UTC가 아닙니다. 세션 경과 시간은 `(time_us - 첫 time_us)/1e6`입니다.
- `seq`: 세션 시작 시 0부터 증가하는 목표 슬롯 번호. 약 20,000us 간격입니다. 읽기 실패나 일정 지연은 번호가 건너뜁니다.
- 두 센서는 순차로 읽으며 `time_us`는 두 센서 읽기 시작 시점입니다. 두 센서의 내부 클록/샘플 시점은 하드웨어 동기화되지 않습니다. 엄밀한 동시 측정이나 하드 실시간 50Hz를 보장하지 않습니다.
- DLPF=3, 내부 출력 목표 50Hz를 설정·읽어 확인합니다. FIFO는 사용하지 않고 최신 레지스터를 읽습니다. 샘플 순번은 호스트 수집 슬롯을 검증하며 내부 센서 샘플의 중복/유실까지 보증하지는 않습니다.

## 6. 무결성 점검과 누락 해석

60초면 대략 3,000행을 기대합니다. 정확히 3,000행일 필요는 없지만 summary와 함께 확인합니다.

- `rows > 0`, `received_hz`가 대략 50(기본 점검 49~51Hz), `reason=duration_complete`인지 확인합니다.
- `missing_slots=0`, `malformed=0`, `read_fail_messages=0`, `timing_anomalies=0`을 우선 목표로 합니다. `missing_slots`는 첫 저장 행 이전의 슬롯과 저장 행 사이 누락 수이며 마지막 저장 행 이후의 손실은 계산할 수 없습니다.
- `timing_anomalies`: 실제 시간 차이와 순번 차이×20ms의 차이가 5ms를 초과한 경우입니다. 이 임계값은 점검용이며 연구 품질 보증 기준은 아닙니다.
- 열 개수, 유한 숫자, 설정 범위를 검사해 잘못된 행은 제외하고 집계합니다. 순번/시간이 중복되거나 역행하면 세션을 중단합니다. 재부팅/재연결 후에는 새 명령으로 새 세션을 시작하세요.
- `near_full_scale_rows`가 있으면 ±2g/±250deg/s 포화 가능성을 확인합니다. 코드를 바꿔 범위를 넓힐 때는 변환 계수, Python 범위 검사, 실험 메타데이터도 함께 수정해야 합니다.
- `max_backlog_bytes`가 커지면 PC 처리 지연일 수 있습니다. 4096바이트 초과는 경고합니다. 지연 중에도 timestamp 기준 주파수는 정상처럼 보일 수 있습니다.
- 모든 경고는 원인을 조사하고 재수집 여부를 판단하세요. 원본을 보존하고 누락 구간을 무조건 0이나 이전 값으로 채우지 마세요. 연속 윈도우가 필요한 학습에서는 간격이 끊긴 구간을 나누거나 제외합니다.

## 7. 과잉 버퍼링·오류 대처

- 115200 baud로 충분히 전송할 수 있도록 짧은 숫자 CSV만 사용합니다. 매 행 터미널 출력·그래프 표시·sleep을 추가하지 않습니다. 파일은 약 1초마다 flush하고 종료 시 닫습니다. 갑작스러운 전원 차단/프로세스 강제 종료에서는 일부 데이터가 손실될 수 있습니다.
- 수집 중 `reset_input_buffer()`를 반복하면 정상 데이터도 버립니다. 이 스크립트는 수집 시작 전에만 초기화합니다. 입력 버퍼를 과도하게 키워 지연을 숨기지 마세요.
- `Access denied` / 포트 열기 실패: 시리얼 모니터·플로터·다른 Python 창을 닫고 실제 COM 포트를 확인합니다.
- 데이터 없음: 업로드된 스케치, 115200 baud, 케이블, 전원을 확인합니다. 일부 개발보드는 포트 오픈 시 리셋되므로 자동 부팅 대기를 둡니다. 필요하면 EN을 눌러 초기화 출력을 먼저 확인하세요.
- FAIL/누락 반복: 배선·전원 안정성·풀업·USB 연결을 확인합니다. 실패 시 전 행을 0으로 저장하지 않습니다.
- CSV를 Excel로 열어 확인할 수 있지만 원본은 덮어쓰지 마세요. 수집 중인 파일을 Excel에서 잠그지 마세요.

## 8. AI 학습 전에 반드시 세션 분할

같은 세션의 인접 샘플은 매우 비슷합니다. 모든 행이나 겹친 윈도우를 무작위로 train/test 분리하면 데이터 누출로 성능이 과대평가됩니다.
먼저 `session_id` 기준으로 train/validation/test를 나누고, 각 집합 안에서 윈도우를 만드세요. 새로운 사람에 대한 성능을 평가한다면 `subject_id` 기준으로 분리하세요. 모든 겹침 윈도우는 같은 집합에 있어야 합니다.
정규화/바이어스 보정의 학습 통계는 train에서만 구해 validation/test에 적용합니다. 라벨, 세션 ID, 피험자 ID, 순번, 절대 timestamp를 기본 12채널 특징에 그대로 넣지 마세요. 장착 위치·축·라벨 기준·피험자·세션별 관찰 사항은 별도 실험 기록으로 보존하세요.

## v2 초기화 수정
사용자가 정상 동작을 확인한 코드에 맞춰 I2C 400kHz, timeout 50ms, PWR_MGMT_1=0으로 변경했습니다. 장치 리셋 명령은 생략하고 ID는 진단 출력합니다. 설정값 읽기 검증은 유지하며 실패 레지스터를 표시합니다. 자이로 바이어스는 빼지 않은 원시 환산값을 저장합니다. 기존 50Hz CSV 형식과 Python은 유지됩니다. 실물 검증은 필요합니다.
